# 维护原则与当前取舍

## 数据归属

规则文本由本仓库持有、分类和发布。sve1r 作为分服务候选数据源，ppmina 作为新增域名发现源，服务官网和实际连接记录作为专项规则的主要证据。输入固定 SHA 可复核，输出不机械跟随上游。

2026-10-14 审查发现 sve1r 的本次九份列表仍来自 2026-02-09；其中 Bilibili 合并表存在 11 个含空格错误域名、媒体 IP CIDR 不规范和大量重复。已按原始 Bilibili 子表修正，再规范格式、策略与归属。

ppmina 数据更新较新，但 direct/proxy 存在 119 个精确同目标交集，direct/reject 277、proxy/reject 119；代理表包含 HSBC，拒绝表包含 OpenAI/HSBC 遥测域名。它的规则无法表达本用户“银行直连/AI可切换”的意图，因此仅用于检查遗漏，不直接导入三大表。该项目 GPL-3.0；以后如复制其可版权内容须重新处理许可，不把它标成 MIT。

## 分类约束

`Config/categories.json` 是配置入口，服务专属覆盖优先，再通用服务、媒体、国内与全球。必选列表每个 `(规则类型, 目标)` 只保留一个归属。可选 OpenAI 共享依赖关闭时，ForeignMedia 中 `intercom.io` 的 Global 兜底仍有用途，因此记录为条件重叠。

精确去重不能证明所有语义冲突消失：`HOST`、`HOST-SUFFIX`、`HOST-KEYWORD`、通配、IP 规则可能覆盖同一连接。专项列表避免 keyword，云租户使用精确 HOST，父域覆盖其子域就不再堆叠同政策子域。宽泛关键词、共享域和大网段保留诊断，不能仅为了零告警隐藏问题。

QX 的“分流匹配优化”开启后按精确度、同级加载顺序决定匹配；关闭时更依赖加载顺序。“优先加载本地分流”、插入资源也会影响顺序。配置顺序是防护层，运行中的具体命中规则才是事实。离线测试明确只检验域名顺序模型，不冒充 QX 内核。

`force-policy=direct` 是内置固定直连；`force-policy=OpenAI` 是让每条命中使用名为 OpenAI 的策略。前者和包含 direct 候选的可切换策略组并不等价。阻断规则不与 `force-policy=China` 混放。

## 网络边界

- QX 直连仍经过本地 VPN 处理、DNS、规则评估；退出 QX 与选择 direct 不是同一种网络状态。
- `dns_exclusion_list` 关闭 Fake-IP 映射，并不等于绕过代理、加密 DNS 或避免污染。默认不再为银行额外扩大这个列表。
- 普通 DNS 默认包含系统解析器；多个 DoH 是并发，不是按顺序备用。启用通用 DoH 会覆盖系统/通用明文 DNS。企业内网域需显式 split-DNS。
- 默认保留 IPv6，提供本机/链路本地/ULA 规则；不把整段 IPv6 强制 direct。OpenAI WebSocket 仍是域名覆盖的 TCP/443；裸 IP 语音 UDP 需官方动态地址和设备验证，不使用全局 UDP/3478 直连捷径。
- `fallback_udp_policy` 只接受具体支持 UDP 的节点名，默认 reject；不能写策略组或 direct 企图透明回退。
- `force-remote-dns` 在当前 QX 原生程序可见，保留现有必要行；它是 DNS 行为改变，仍需核对实际策略及结果，不能当无意义尾缀删除。

## 发布与回滚

更新参考输入不会自动改本仓库输出；审查、测试、生成配置后才发布。推荐先在独立分支/PR 汇总，再使用完整 commit SHA 验收。合并到 master 才改变 master 订阅的下一次更新。回滚使用上一个完整 SHA 和对应配置，不回退 DNS/策略 UI 状态的事实记录。

公开模板不含私有节点和证书。私有可导入文件保存在仓库之外。源文件已更新、Git 已推送、Raw 已校验和设备已切换是四个独立状态，报告必须分别写明。
