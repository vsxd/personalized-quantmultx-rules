# 维护原则与网络边界

规则内容、归属和发布由本仓库独立维护。sve1r 与选定的 MIT v2fly 输入保留许可和来源；其他 QX/Surge/Clash 项目提供候选发现与设计比较，许可与是否采纳见 THIRD_PARTY.md。参考更新流程见 agent-update-guide.md。参考仓库数量不等于已完整验证其中全部服务，include、regex 和发布分支必须单独追踪。

本轮不再以“零语法错误”作为可发布标准。审查包括实际默认启用的全部资源、禁用资源独立语法/范围、父子后缀、不同规则类型、策略与 DNS/接口选项、IP 范围、品牌顶级域名和最终生成配置。只允许可复核的精确例外；保留原因不能自动让过度覆盖变合理。

旧 User-Agent 规则在加密流量上不可靠，且会混淆“应用身份”和“目标服务”；旧 Netflix/Akamai/AWS/媒体捕获 IP 没有当期服务归属保证，本轮移出。必要裸 IP 清单必须有官方来源、核验日期和后续更新机制。删除旧规则不等于证明某个服务的全部动态端点都已覆盖。

## 网络边界

- force-policy=direct 是固定内置直连；force-policy=OpenAI 等命名策略组仍受当前选择影响。模板首候选不代表设备已经切换。
- QX direct 仍经过本地 VPN、DNS 和规则评估；退出 QX 与选择 direct 不是同一种状态。
- dns_exclusion_list 只关闭 Fake-IP 映射；excluded_routes 才绕过 QX，修改后还可能需要重连。
- 普通 DNS 默认包含系统解析器。启用通用 DoH/DoQ 会改变系统/普通 DNS 的使用方式；企业内部域名需要明确 split-DNS。解析传输加密不保证结果未过滤。
- 不批量继承无实测依据的 force-remote-dns。它是 DNS 行为改变，不能当作无意义尾缀；删除或保留必须记录原因。
- 默认保留 IPv6。域名覆盖、AAAA、裸 IPv6、QUIC、语音分别验收，不使用全局 UDP/3478 直连捷径。
- fallback_udp_policy 用于被选中节点不支持 UDP 的情况，只接受合适的具体节点名；默认 reject，不能写策略组或 direct 作为透明回退。
- OpenAI/Claude 的文档网络 allowlist 是连通性要求，不证明每个共享供应商都专属于 AI；共享依赖影响其他调用方，单独可选。
- 分流匹配优化、优先本地和插入资源影响实际顺序；离线模型不能冒充 QX 内核。

## 发布与回滚

在分支内完成源审查、规则修复、文档与测试后，通过 PR 合入 master。master 是唯一发布分支；main 不再维护。先验证待合入提交的 CI，再合入并回读实际 Raw URL。源文件已修改、提交已推送、Raw 已一致和设备已切换是不同状态，分别报告。

稳定配置使用完整提交 SHA；更新到新版本时重建同一版本全部资源。回滚使用上一完整 SHA 和其对应配置，不混用旧路径与新规则。公开模板没有私有节点/CA；私有构建在仓库外保存，导入前备份只存在于 QX 缓存的节点。仓库维护不自动修改活动 QX 配置。
